# 核查清单（只读）

核查不改文件，只产报告：每条给 `文件:行号`、判定、后果、一条修法。

| # | 检查 | 判定 | 严重度 |
|---|---|---|---|
| A1 | 一次性事实混进 skill | 正文出现绝对路径（`C:\…`、`/d/…`）、条目 id、某次字节数、本机版本号、“我上次把配置改成…” | high：换项目即失效，读者照做会错 |
| A2 | description 概括流程 | 描述里出现步骤、数量、阶段名 | high：正文被跳过，实测会漏步骤 |
| A3 | 叙事冒充能力 | 大段“我们先…然后发现…”的调试过程，只有结论值得留 | medium：挤占 context，且读者分不清哪句是判据 |
| A4 | 环境假设未声明 | 依赖某 CLI/服务/账号，正文没写前置或降级路径 | high：读者在最后一步才发现跑不通 |
| A5 | 体积失控 | `SKILL.md` 超 150 行且无 `references/` 拆分；或同一事实写两处 | low：变慢，长期分叉 |
| A6 | 断链与重叠 | 引用的相对路径不存在；或与相邻 skill 的触发面重叠到无法区分 | medium；重叠是 high（触发被稀释） |
| A7 | 触发词不覆盖真实说法 | 只有术语，没有中文口语/错误形状/近邻反例 | medium：装了但不触发 |

## 机械部分

```bash
python scripts/check_skill.py --all <skills-dir>
```

覆盖 A1（绝对路径，warn）、A2 的机器可判部分（长度/第一人称）、A5（行数/同名文件）、A6（相对链接断链）。A3、A4、A7 需要人读，脚本不判断。

## 报告骨架

```markdown
### <skill-name>（N 行 / M 字节）
- [A2/high] SKILL.md:3 description 概括了“先…再…”，后果：读者跳过正文只做第一步。修法：删掉步骤，只留触发句。
- [A4/high] SKILL.md:57 要求 Codex CLI，正文无前置说明。修法：该段加“需要 X；若无则跳到 Y”。
```

没有问题的 skill 也要列出“已查、未发现”，否则“没提”与“没问题”不可区分。
